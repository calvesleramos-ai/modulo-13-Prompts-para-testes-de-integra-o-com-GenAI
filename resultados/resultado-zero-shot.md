# Casos de teste de integração — OpenAlex

Os cenários abaixo são especificações para automação com `pytest` e `requests`. Substitua os endpoints internos (`<rota de pesquisa>` e `<rota de análise>`) pelos definidos pelo back-end. Nos testes do back-end, prefira interceptar as chamadas HTTP à OpenAlex com mocks; assim, os resultados são reproduzíveis e não dependem de rede, cotas ou mudanças nos dados externos.

## Premissas a confirmar

- A API OpenAlex é acessada em `https://api.openalex.org`; a pesquisa de autores usa `GET /authors?search=...` e a recuperação de trabalhos pode usar `GET /works?filter=author.id:<id>`. Confirmar filtros, paginação e campos na documentação vigente.
- Os identificadores de trabalho são a chave de unicidade. Um trabalho conta uma vez se ao menos uma instituição de sua autoria for diferente da instituição de referência, mesmo que haja vários autores ou instituições externas.
- O contrato do back-end define os formatos de sucesso e erro, os limites de paginação e a política de retry para `429`/erros transitórios. Os casos abaixo verificam essa política sem impor um número de tentativas não especificado.
- Para vínculos institucionais, os dados relevantes são os vínculos de autoria e as instituições retornadas pela OpenAlex. Dados ausentes não devem ser interpretados silenciosamente como colaboração.

## Diretrizes de automação

- Use `pytest` com fixtures para configurar o cliente e as respostas simuladas; use `requests` para chamar as rotas reais do back-end no ambiente de integração.
- Intercepte apenas as chamadas à OpenAlex nos testes automatizados, validando método, URL, parâmetros, paginação e número de tentativas. Reserve chamadas reais à API para testes de contrato controlados, se necessários.
- Para os casos críticos, valide tanto o total quanto os IDs dos trabalhos que compõem o total. Isso detecta duplicidades e classificações erradas que uma simples asserção numérica poderia ocultar.
- Mantenha IDs de autor, trabalho e instituição fictícios ou fixtures estáveis; não dependa de ordenação da API, salvo se o contrato a garantir.
- Execute INT-01/02/14 com o front-end e back-end integrados; execute os demais na fronteira do back-end com transporte HTTP simulado. Os endpoints e o formato exato de resposta dependem do contrato da aplicação.
